# Evaluation Pipeline Report

## Architecture

The pipeline is implemented as an Airflow DAG (`dags/evaluate_agent.py`) with 4 tasks:

```
prepare_run -> run_agent -> run_eval -> summarize_and_log
```

- **prepare_run**: Reads Airflow params, creates `runs/<run-id>/config.json`
- **run_agent**: Runs `mini-extra swebench` on SWE-bench instances, outputs trajectories and `preds.json` to `runs/<run-id>/run-agent/`
- **run_eval**: Runs `swebench.harness.run_evaluation` on `preds.json`, outputs report to `runs/<run-id>/run-eval/`
- **summarize_and_log**: Parses eval report, writes `metrics.json` and `manifest.json`, logs params and metrics to MLflow

## Artifact Layout

```
runs/
  <run-id>/
    config.json        # run parameters
    manifest.json      # paths to all artifacts
    metrics.json       # resolved, total, resolve_rate
    run-agent/
      preds.json       # agent predictions
      <instance-id>/   # per-instance trajectories
    run-eval/
      *.json           # swebench evaluation report
```

## How to Trigger

1. Start Airflow: `bash run-airflow-standalone.sh`
2. Open http://localhost:8080
3. Trigger `evaluate_agent` DAG with params:
   - `split`: test
   - `subset`: verified
   - `workers`: 2
   - `model`: nebius/meta-llama/Llama-3.3-70B-Instruct
   - `task_slice`: 0:2
   - `custom_run_id`: run-001

## How to Rerun by run-id

1. Set `custom_run_id` param to the desired run-id when triggering
2. All artifacts will be written to `runs/<run-id>/`
3. Use `cat runs/<run-id>/config.json` to inspect the original configuration

## MLflow

- Tracking URI: `sqlite:///mlflow.db`
- Experiment: `evaluate_agent`
- View UI: `mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000`
- Each run logs: params, metrics (resolved, total, resolve_rate), config.json, metrics.json
